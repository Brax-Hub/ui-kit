## Directory Conventions

- `src/routes/` — one file per route, `createFileRoute`, `validateSearch` for URL state
- `src/components/ui/` — shadcn primitives only, no business logic
- `src/components/<feature>/` — feature components, under 200 lines each
- `src/server/` — `createServerFn` handlers (`*.functions.ts`), `db/` (schema, policies, client), `hub/` (identity, ai, mail, contacts), `jobs/`, `env.ts`
- `drizzle/` — generated migrations with the policy SQL as custom statements
- `deploy/hub/` — the compose overlay and the edge block
- `design/` — manifest and decisions for the Claude Design round trip

## Rules

1. URL state over `useState` for anything a user would bookmark or share.
2. Browser-only APIs live inside `useEffect` or `clientOnly`.
3. Secrets, the module credential and database clients are reached only through `src/server/*.server.ts`.
4. Every private `createServerFn` has `.middleware([requireRole(...)])` and `.validator(zod)`; `beforeLoad` is UX only.
5. Roles come from `memberships`, synced from the hub's headers on first sight; a header alone never authorizes.
6. Every query runs inside `asMember(context, tx => ...)` or `asService(reason, tx => ...)`; nothing else touches the database.
7. Every table has `tenant_id`, `force row level security`, explicit grants to `app_rw` and four policies using `(select app.member_id())` / `(select app.tenant_id())`, with an index on every column a policy reads.
8. Views use `security_invoker = true`; `security definer` functions set `search_path` and revoke `public`.
9. Every structural migration on a hub has a snapshot first; policies ship in the same migration as their table.
10. Every turn ends with `npx tsc --noEmit` exit `0`, the security scan, and the RLS test after schema or policy changes; before a release `npm run build` and `docker build`.
11. Every sidebar route is listed in the smoke suite's `ROUTES` so the placeholder-page check covers it.
12. Browser scripts run as the stub edge's `DEV_MEMBER`; they never log in and never carry credentials.
13. Scheduled and background code runs under `asService` with no member: it validates scope itself, is idempotent and logs every run.
14. AI, mail and contacts go through the hub's scopes; a scope the hub has not enabled is shown as a state, never an error.
15. The app serves itself under `/modules/<slug>/` and sends `frame-ancestors 'self'`; it never shows a sign-in screen.
